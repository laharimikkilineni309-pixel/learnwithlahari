# QA to Software Developer: Your First 30 Days

Moving from QA to development does not mean starting from zero. Your experience investigating failures, reading APIs, understanding requirements, and automating workflows is valuable. The new skill is **owning the application code**, not just validating it.

## Week 1: Choose a language and build daily

Pick **Java** if you want a Spring Boot backend path, or **Python** if you want FastAPI and AI-focused backend work. Focus on variables, control flow, functions, classes, collections, and error handling. Write a small program every day; don't just watch tutorials.

**Practice:** Build a command-line task tracker that creates, lists, updates, and deletes tasks. Store tasks in memory first.

## Week 2: Learn HTTP, APIs, and Git

Understand HTTP methods, status codes, JSON, request validation, and authentication basics. Practice branching, committing, pull requests, and reviewing your own changes.

**Practice:** Design endpoints for the task tracker: `GET /tasks`, `POST /tasks`, `PATCH /tasks/{id}`, and `DELETE /tasks/{id}`. Document expected request and response examples.

## Week 3: Build a real backend

Implement the endpoints using Spring Boot or FastAPI. Add SQLite or PostgreSQL, validation, meaningful errors, and tests. Separate routes, business logic, and persistence.

**Practice:** Make the task tracker persist data after restart. Include both successful and invalid-input scenarios.

## Week 4: Ship and explain your work

Containerize or deploy your API, write a README, and add a CI workflow that runs tests. Be able to explain architecture, tradeoffs, failure handling, and what you would improve.

**Portfolio checkpoint:** Share a working API, public repository, setup instructions, and a short demo. Describe what you built—not only what you tested.

## What to study alongside this plan

- **Data structures:** arrays/lists, hash maps, strings, and time complexity.
- **SQL:** joins, constraints, transactions, and indexes.
- **Frontend fundamentals:** HTML, CSS, JavaScript, then React if full-stack is your goal.
- **Engineering practices:** debugging, logging, security basics, and maintainable code.

## Common mistakes to avoid

- Learning three languages simultaneously without building anything.
- Completing courses but never deploying a project.
- Listing technologies on your résumé without being able to explain a real implementation.
- Treating QA experience as irrelevant instead of showing how it improves engineering decisions.

## A sustainable schedule

If you have one hour, spend 15 minutes reviewing a concept, 35 minutes writing code, and 10 minutes documenting what worked. Consistency matters more than perfect uninterrupted study time.

**Next step:** Build your first endpoint and write down the tradeoffs you made. That becomes the foundation for your first developer portfolio story.
