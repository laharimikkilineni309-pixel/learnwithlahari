REST API testing: a reusable checklist

Go beyond checking 200 OK with a systematic approach to API quality.

1. Contract and behavior

Validate method, endpoint, required headers, response schema, types, and business rules.

2. Positive and negative paths

Try valid input, missing fields, invalid types, boundary values, duplicate submissions, and malformed JSON.

3. Security and permissions

Verify authentication, authorization for each resource, sensitive data exposure, and rate limiting.

4. Reliability and observability

Check timeouts, retries, idempotency, correlation IDs, and meaningful error responses.

5. Data and integration

Confirm the persisted state and downstream effects, then clean up test data.

Key takeaway

Example: a POST returning 201 can still be wrong if it creates two records.
